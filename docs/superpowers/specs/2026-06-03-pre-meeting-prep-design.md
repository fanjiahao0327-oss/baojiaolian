# 见前准备 MVP 设计

## 背景

AI 保险教练第一阶段已经完成“客户卡点跟进”：代理人在面谈后、微信跟进前或电话跟进前，可以复盘客户异议并生成下一步话术。

第二阶段聚焦更靠前的销售时刻：代理人见客户前，需要在很短时间内判断这次面谈应该从哪里切入、先问什么、暂时不要聊什么，以及客户可能会出现哪些拒绝或异议。

这个功能不做成长报告，也不做线下面谈现场实时救场。它的定位是代理人见客户前 2 到 5 分钟打开小程序快速看一眼的“面谈作战卡”。

## 目标用户

第一优先级：

- 新人保险代理人：见客户前不知道该从关系、需求、保障还是资产话题切入。
- 有经验但缺方法论的代理人：知道客户背景，但需要把信息整理成一套有顺序的面谈策略。
- 遇到具体客户但档案不完整的代理人：只掌握零散背景，也希望先获得一版可执行的见前准备。

不作为 MVP 核心：

- 团队长训练和评分。
- 复杂客户阶段管理。
- 长篇财富规划报告。

## 产品定位

入口名称：见前准备。

它解决的不是“客户已经拒绝后怎么接”，而是“见面前我应该如何开始这次面谈”。

第一版目标：

- 让代理人用已有客户档案或临时补充信息，快速生成一张面谈作战卡。
- 帮代理人避免过早讲产品、收益、价格或方案。
- 帮代理人把顾问式销售流程前置到见面前。

## 入口与信息架构

小程序教练页内的工作模式从两个扩展为三个：

- 客户卡点跟进
- 见前准备
- 完整诊断

默认入口仍可保持“客户卡点跟进”，但用户可以在同一块模式切换区进入“见前准备”。

Web 端本轮不做重点入口。后端 API 保持模式兼容，后续需要时再同步 Web 表单。

## 输入设计

第一版支持两种输入来源：

- 已有客户档案：代理人可以选择已有客户，系统读取该客户的 KYC 快照作为背景。
- 临时补充信息：即使没有客户档案，也可以直接填写少量关键背景。

表单字段尽量少，优先适合手机端快速填写。

必填：

- 这次见面目的：初次面谈、二次见面、保单检视、转介绍客户、老客户加保、其他。
- 本次见面背景或触发点：例如“朋友介绍，客户刚生二胎”“老客户想看看已有保单够不够”“客户最近聊到孩子教育”。

选填：

- 已知客户背景：年龄、职业、家庭、收入、已有保障、资产偏好等，支持一两句话。
- 我最担心的问题：例如“怕客户觉得我推销”“怕聊不到保险”“怕客户只问收益”“怕客户说没预算”。
- 希望这次达成什么：建立信任、了解需求、约下次、做保单检视、进入方案沟通。

如果用户选择了已有客户，客户档案信息作为底层背景；临时补充信息作为本次会面的最新上下文，优先级高于旧档案。第一版不把临时补充自动写回客户档案，只在输出中提醒哪些信息值得后续补充。

## 输出设计

AI 输出固定为五段，形成“面谈作战卡”。

### 1. 客户初步判断

判断客户大概率处于什么状态：

- 关系信任还没建立。
- 有需求苗头但尚未强化。
- 已经有保障但不清楚是否足够。
- 只是在了解收益或产品，尚未进入真实需求。
- 可能存在家庭责任、教育、养老、医疗、资产保全等切入点。

要求：

- 不编造客户没有提供的信息。
- 对不确定的判断明确写成“可能”。
- 只给 2 到 3 条最重要判断。

### 2. 这次别急着做什么

提醒代理人避免见面一开始走偏，例如：

- 不要一上来讲产品。
- 不要急着报价或算收益。
- 不要先问敏感财务数字。
- 不要把客户的普通聊天强行转成保险推销。

这一段要短，像教练提醒，不要说教。

### 3. 开场切入话题

给 2 到 3 个自然开场，可直接用于见面前准备。

要求：

- 像真人说话，避免培训腔。
- 能从客户提供过的背景自然切入。
- 先建立关系和理解，再进入保险相关问题。

### 4. 提问顺序

给出这次面谈建议的问题顺序：

- 先问什么。
- 再问什么。
- 暂时别问什么。

重点体现顾问式销售的阶段顺序：先找需求，再强化需求，再找不足，最后才进入方案。

### 5. 可能异议预案

预判客户可能说的话，并给出下一句接法。

常见异议包括：

- 没兴趣。
- 太忙了。
- 我有保险了。
- 我没预算。
- 我先了解一下。
- 收益怎么样。

要求：

- 每个预案都要短。
- 不反驳客户。
- 不催促客户决定。
- 优先用提问把客户带回真实需求。

## 知识库使用

第一版复用现有 `src/lib/knowledge.ts` 中的顾问式销售方法论，重点使用：

- 面谈阶段流程图和禁止跳步规则。
- 阶段 0 的关系激活和社交切入。
- 阶段 1 的找需求问题。
- 积极导向提问。
- 常见异议处理。

不在本阶段重构大规模知识库，也不把分红险资料完整拆入新模块。分红/储蓄险资料增强作为后续第三阶段处理。

## 数据与保存

第一版复用现有对话保存能力。

- 若用户选择了客户，本次见前准备关联该客户。
- 若未选择客户，作为普通对话保存。
- 对话标题格式为“见前准备：客户名/见面目的”。
- 结果支持继续追问，例如“帮我改成更熟人一点的开场”“客户如果问收益怎么接”。
- 不自动更新 KYC 档案，只输出“建议补充到客户档案的信息”。

## 后端模式

`POST /api/coach` 增加新的模式：

- `mode: "pre_meeting_prep"`
- payload 字段为 `preMeetingPrep`

服务端根据模式选择不同的输入校验、标题生成和模式指令。

见前准备模式不输出 `[KYC_UPDATE]` 标签。若 AI 发现值得补充的客户信息，只在作战卡末尾或第五段后用自然语言提醒代理人后续手动补充。

积分规则沿用现有 AI 对话扣分逻辑，不在 MVP 中新增独立定价。

## 小程序交互

小程序教练页的工作模式切换区新增“见前准备”。

当选择“见前准备”时：

- 顶部 Tab 左侧文案显示“见前准备”。
- 显示轻量表单卡片。
- 仍保留顶部客户选择入口。
- 点击生成后跳转到教练指导区，使用现有消息列表展示结果。
- 加载状态沿用当前完整返回等待提示。

视觉上复用“客户卡点跟进”的表单结构，避免新增一套复杂 UI。

## 安全与合规

- 继续使用现有登录、积分、速率限制和提示词注入检测。
- 用户输入中的提示词攻击同样需要检测。
- 不泄露系统提示词、知识库来源、底层资料、数据库结构。
- 输出结尾继续保留合规免责声明。
- 不做具体产品推荐，不承诺收益，不替代保险公司正式条款。

## 非目标

MVP 暂不做：

- Web 端入口。
- 长篇见前策略报告。
- 团队训练材料。
- 面谈现场实时逐句陪聊。
- 自动更新客户档案。
- 分红险/储蓄险知识库大规模重构。
- 单独的见前准备历史列表或客户阶段看板。

## 验收标准

- 用户能在小程序教练页进入“见前准备”。
- 用户可以选择已有客户，也可以不选客户直接填写临时背景。
- 用户填写见面目的和本次背景后即可生成结果。
- AI 输出包含五段：客户初步判断、这次别急着做什么、开场切入话题、提问顺序、可能异议预案。
- 输出内容短、自然、可在见客户前快速阅读。
- 输出不编造未提供的客户事实。
- 结果可以保存为对话，并支持后续追问。
- 现有“客户卡点跟进”和“完整诊断”不被破坏。
- 小程序端使用稳定的非流式完整响应展示。

## 后续迭代

第二阶段 MVP 上线后，再按优先级推进：

1. 面谈复盘：把面谈过程转成跟进计划和客户档案更新建议。
2. 分红/储蓄险知识库增强：拆分用户提供的分红顾问资料。
3. 团队训练：把优秀作战卡和卡点拆解沉淀为主管训练材料。
