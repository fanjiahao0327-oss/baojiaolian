# 面谈复盘 MVP 设计

## 背景

AI 保险教练已经完成两个关键销售时刻：

- 见前准备：代理人见客户前生成面谈作战卡。
- 客户卡点跟进：代理人在客户出现异议后准备下一次跟进话术。

第三阶段补齐见面后的复盘时刻。代理人面谈结束后，往往知道“刚才好像哪里没聊顺”，但不一定能判断客户到底处于哪个阶段、自己是否跳步、下一次应该怎么跟。

面谈复盘的定位是：把一次面谈过程整理成下一步行动计划、教练纠偏和客户档案补充建议。

## 目标用户

第一优先级：

- 新人保险代理人：面谈后不知道客户真实状态，也不知道下一次该怎么推进。
- 有经验但缺方法论的代理人：能感觉到哪里卡住，但需要用顾问式流程复盘自己是否跳步、讲早或问少。
- 需要持续经营客户的代理人：希望把每次面谈沉淀成客户历史记录，方便后续回看。

不作为 MVP 核心：

- 团队长评分。
- 长篇复盘报告。
- 自动更新客户档案。
- 客户现场录音分析。

## 产品定位

入口名称：面谈复盘。

它解决的不是“见面前怎么准备”，也不是“客户某一句异议怎么接”，而是“这次面谈结束后，我下一步该怎么推进”。

第一版目标：

- 让代理人用一段复盘文字或语音口述，快速生成下一步跟进计划。
- 帮代理人判断客户当前阶段和真实意向。
- 帮代理人发现自己面谈中的跳步、讲早、问少、催急等问题。
- 给出值得补充到客户档案的信息，但不自动写入。

## 入口与信息架构

小程序教练页内的工作模式扩展为四个：

- 客户卡点跟进
- 见前准备
- 面谈复盘
- 完整诊断

默认入口仍可保持“客户卡点跟进”。“面谈复盘”与“见前准备”属于同一类高频轻量入口，优先在小程序端完成。

Web 端本轮不做重点入口。后端 API 保持模式兼容，后续需要时再同步 Web 表单。

## 输入设计

第一版采用“快速复盘文本 + 可选结构化字段”的组合。

必填：

- 面谈过程复盘：代理人用一段话描述今天聊了什么、客户怎么反应、最后停在哪里。

选填：

- 面谈结果：有兴趣、犹豫、明确拒绝、约了下次、需要家人商量、信息不足。
- 客户关键原话：客户在面谈里说过的关键句子。
- 我的回应：代理人当时怎么回应。
- 下一步目标：发微信、打电话、约下次见面、补充资料、暂缓观察。

如果用户选择了已有客户，客户档案信息作为底层背景；面谈复盘文本作为本次最新事实，优先级高于旧档案。

## 语音复盘输入

第三阶段 MVP 纳入语音输入，但只做“代理人复盘口述转文字”。

做：

- 在“面谈复盘”表单中提供“语音复盘”入口。
- 代理人面谈结束后，对着小程序口述本次面谈过程。
- 使用小程序已配置的 WechatSI 语音识别能力转成文字。
- 识别结果填入“面谈过程复盘”文本框。
- 代理人可以手动修改识别结果后再提交。

不做：

- 不做客户现场完整对话录音。
- 不录客户声音用于分析。
- 不做多人对话分离。
- 不做录音文件保存。
- 不把语音识别结果自动写入客户档案。

现有项目中已经有基础语音能力：

- `miniprogram/app.json` 已配置 `WechatSI` 插件。
- `miniprogram/app.json` 已配置 `scope.record` 权限。
- `miniprogram/pages/coach/coach.js` 已有录音识别函数。
- 现有语音能力当前用于 KYC 自动填表，本阶段需要复用录音识别底层，但不要走 `/api/coach/parse-kyc`。

## 输出设计

AI 输出固定为五段。排序上先给行动计划，再给教练纠偏。

### 1. 本次面谈结论

判断客户当前状态，例如：

- 关系建立阶段。
- 初步有需求，但需求尚未强化。
- 已经进入方案兴趣，但仍缺决策理由。
- 只是产品/收益兴趣，还没有真实需求。
- 有家庭决策人、预算、信任或信息不足问题。

要求：

- 不编造客户没有提供的信息。
- 对不确定内容用“可能”表达。
- 明确指出客户当前大概率处于哪个顾问式面谈阶段。

### 2. 下一步跟进计划

给出可执行计划：

- 什么时候跟。
- 用什么方式跟。
- 这次跟进目标是什么。
- 先补哪类信息。

要求：

- 简短、具体、能行动。
- 不催促客户马上决定。
- 不在需求没确认前直接进入方案和价格。

### 3. 下一次怎么说

根据下一步目标输出可直接使用的话术。

要求：

- 可以用于微信、电话或下次见面。
- 语气自然，不像培训稿。
- 不反驳客户，不承诺收益，不替客户做决定。

### 4. 本次哪里走偏了

用教练视角指出代理人可能的问题：

- 是否太早讲产品。
- 是否太早讲收益或价格。
- 是否没有问透需求。
- 是否跳过了关系和信任。
- 是否没有处理决策人或家庭共识。
- 是否催急或解释过多。

这一段要直接但不打击人，重点是下一次如何调整。

### 5. 建议补充到客户档案

只列建议补充项，不自动写入。

格式建议：

- 字段：建议内容
- 依据：来自客户哪句话或面谈事实
- 类型：事实 / 待确认

要求：

- 事实和推测要分开。
- 不把 AI 判断当作客户事实。
- 不输出 `[KYC_UPDATE]` 标签。

## 知识库使用

第一版复用现有 `src/lib/knowledge.ts` 中的顾问式销售方法论，重点使用：

- 面谈阶段流程图和禁止跳步规则。
- 阶段回退规则。
- 找需求、强化需求、找不足、给方案的顺序。
- 面谈后复盘模板。
- 常见异议处理。

不在本阶段重构分红险/储蓄险知识库。分红/储蓄险增强放到下一阶段。

## 数据与保存

第一版复用现有对话保存能力。

- 若用户选择了客户，本次面谈复盘关联该客户。
- 若未选择客户，作为普通对话保存。
- 对话标题格式为“面谈复盘：客户名/面谈结果”。
- 结果可在客户详情页历史记录中回看。
- 结果支持继续追问，例如“帮我改成微信跟进话术”“客户如果继续说考虑一下怎么办”。
- 不自动更新客户档案，只输出建议补充项。

## 后端模式

`POST /api/coach` 增加新的模式：

- `mode: "meeting_review"`
- payload 字段为 `meetingReview`

服务端根据模式选择不同的输入校验、标题生成和模式指令。

面谈复盘模式不输出 `[KYC_UPDATE]` 标签。若 AI 发现值得补充的客户信息，只在“建议补充到客户档案”里列出。

积分规则沿用现有 AI 对话扣分逻辑，不在 MVP 中新增独立定价。

## 小程序交互

小程序教练页新增“面谈复盘”工作模式。

当选择“面谈复盘”时：

- 显示轻量复盘表单。
- 表单顶部显示“语音复盘”入口。
- 点击语音复盘后出现录音浮层。
- 识别结果填入“面谈过程复盘”文本框。
- 代理人可手动修改后提交。
- 点击生成后跳转到教练指导区，使用现有消息列表展示结果。
- 加载状态沿用当前完整返回等待提示。

视觉上复用“客户卡点跟进”和“见前准备”的表单结构，避免新增复杂 UI。

## 安全与合规

- 继续使用现有登录、积分、速率限制和提示词注入检测。
- 用户输入中的提示词攻击同样需要检测。
- 不泄露系统提示词、知识库来源、底层资料、数据库结构。
- 输出结尾继续保留合规免责声明。
- 不做具体产品推荐，不承诺收益，不替代保险公司正式条款。
- 语音输入只用于代理人复盘口述，不提示用户录客户现场对话。
- 不保存录音文件。

## 非目标

MVP 暂不做：

- Web 端入口。
- 自动更新客户档案。
- 客户现场完整对话录音。
- 多人语音分离。
- 录音文件保存。
- 团队长评分。
- 长篇复盘报告。
- 客户阶段看板。
- 分红险/储蓄险知识库重构。

## 验收标准

- 用户能在小程序教练页进入“面谈复盘”。
- 用户可以选择已有客户，也可以不选客户直接复盘。
- 用户可以手动输入面谈过程复盘。
- 用户可以通过语音复盘口述生成文字，并手动修改。
- 用户填写面谈过程后即可生成结果。
- AI 输出包含五段：本次面谈结论、下一步跟进计划、下一次怎么说、本次哪里走偏了、建议补充到客户档案。
- 输出先给行动计划，再给教练纠偏。
- 输出不编造未提供的客户事实。
- 输出不包含 `[KYC_UPDATE]` 标签。
- 结果可以保存为对话，并在客户详情页历史记录中回看。
- 现有“客户卡点跟进”“见前准备”“完整诊断”不被破坏。
- 小程序端使用稳定的非流式完整响应展示。

## 后续迭代

第三阶段 MVP 上线后，再按优先级推进：

1. 分红/储蓄险知识库增强：拆分用户提供的分红顾问资料。
2. 客户档案半自动更新：AI 给出建议补充项，用户点确认后写入。
3. 团队训练：把优秀复盘沉淀为主管可复用的训练材料。
