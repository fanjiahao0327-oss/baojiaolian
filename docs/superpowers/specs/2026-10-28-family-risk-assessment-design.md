## 0. 一页结论

把现有面向代理人的「领展智教练」，改造成面向客户（C 端）的「家豪 AI 家庭风险测评」：

> 陌生客户匿名进来 → AI 用混合式提问分诊 + 深挖 → 免费看到家庭风险地图和 3 个核心风险 → 1 元解锁完整报告 → 想落地的人预约家豪的一对一诊断。

V1 的目标不是卖保险，而是**获客**：把「不愿意一上来就把家庭情况告诉代理人的陌生客户」，转化成可联系、可预约、有信任基础的线索。产品不推荐具体产品/公司，不承诺收益，不亮未授权身份，对话内容零存储。

## 1. 背景与转向

### 1.1 原产品

现有仓库是面向保险代理人的 AI 教练（小程序「领展智教练」+ Web 工作台）：代理人填 KYC 表单，AI 给「卡点诊断 → 推演方向 → 建议话术」。已上线，但获客/使用效果不佳。

### 1.2 转向判断

- 陌生客户不愿意把家庭信息直接交给代理人，但愿意先跟 AI 聊。
- 公域内容在 930 新规后不能留联系方式、不能以资料为诱饵导流；「留资 → 加微信」的捷径被堵死。
- 知识库里已经有一份 15 题客户自测问卷和一份意向征询函，但**目前没有合规的公开投放出口**（见 `转化工具/README.md`）。
- 2026-10-27 战略判断提出「AI 原生平台 = 客户第一触点是不是 AI」「线上做获客、线下做深度 KYC」。

**结论：** 做一个客户可匿名使用、可付费、可预约的 AI 风险测评工具，把它作为合规的公开出口和 AI 第一触点；成交仍在线下由人完成。

### 1.3 为什么复用现有小程序

- 现有 AppID、主体、认证、备案、微信支付/虚拟支付配置、服务器域名白名单都已就绪。
- 现有后端已经跑通 DeepSeek 调用、Neon 数据库、合规守卫、知识库、微信登录、支付回调。
- 现有小程序仅 25 个文件、约 4.4k 行，前端重写成本可控。
- 旧版 B 端产品效果不佳，用户已确认**彻底放弃**，直接替换，不做过渡。

## 2. 目标与非目标

### 2.1 V1 目标

1. 客户在 15 分钟内完成一次有价值的家庭风险测评，拿到可保存、可转发的报告。
2. 有相当比例客户愿意付 1 元解锁完整报告（验证付费意愿）。
3. 有相当比例客户愿意主动预约一对一诊断（核心获客指标）。
4. 全程不推荐具体产品、不承诺收益、不亮未授权身份、不保存对话内容。

### 2.2 V1 非目标

- 不做产品推荐、产品报价、投保链接、收益演示。
- 不做代理人端 CRM、客户管理、历史报告云端。
- 不做账号体系、积分体系、会员订阅。
- 不做语音输入、多语言、多角色。
- 不做分享追踪、裂变、分销。
- 不接第三方广告或流量平台。

## 3. 用户与场景

### 3.1 用户

- **主用户（C 端客户）**：从自媒体内容进入小程序的陌生客户，年龄与资产不预设。AI 按客户自述分诊，覆盖保障、医疗、教育、养老、传承、家企、婚姻等方向。
- **次级用户（家豪本人）**：查看预约线索、回复客服、决定是否线下跟进。

### 3.2 场景

客户在抖音/小红书/知乎/视频号看到内容 → 搜索或点击小程序 → 匿名开始测评 → 看到自己的风险地图 → 花 1 元看完整报告 → 预约或先问一句 → 家豪线下联系、做深度 KYC 与方案。

### 3.3 关键约束

- 客户不需要注册、不需要手机号即可开始测评。
- 客户可随时退出；本地保存，服务器不保存对话内容。
- 手机号只在客户主动预约时收集，且加密存储。
- 报告不出现产品名、公司名、费率、收益承诺、理赔承诺、贬低同业、核保预判、恐吓表达。

## 4. 定位与合规边界

### 4.1 产品定位

**家庭风险测评与风险教育工具**，不是保险产品销售页面，也不是保险咨询合同。

- 付费 1 元是「报告生成服务费」，不是保险咨询费，不构成投保建议。
- 报告是「AI 辅助生成的风险自查参考」，最终方案需线下核对合同与事实。

### 4.2 红线（来自 `930合规速查卡.md`，C 端适用）

| # | 红线 | 产品处理 |
|---|---|---|
| 1 | 不留联系方式（含谐音、二维码、变相写法） | 小程序内不出现电话/微信号/二维码；承接只走预约表单与小程序客服 |
| 2 | 不以资料为诱饵导流 | 报告是付费产品，不是「加微信领取」 |
| 3 | 无认证不称保险身份 | V1 个人介绍不写「保险从业者/国寿年丰」；等公司授权+平台认证后再补 |
| 4 | 不自创头衔 | 只写「家豪」+ 真实经历（京东 4 年运营、专注家庭风险与传承） |

## 5. 客户旅程

| 步骤 | 客户看到 | AI 在做什么 | 系统写入 |
|---|---|---|---|
| 1 首页 | 品牌 + 个人介绍（安全版）+ 隐私承诺 + 免责声明 + 「开始测评」 | — | 无 |
| 2 开场 | 「你家现在最让你不踏实的是什么？」+ 3–4 个话题入口（钱够不够花 / 生病怎么办 / 孩子教育 / 父母养老 / 家业传承） | 从第一段话提取风险线索 | 匿名事件：`session_start` |
| 3 分诊 | 追问 1–2 轮 | 输出主风险域（1–2 个）+ 次风险域 | 无 |
| 4 深挖 | 半结构化问题（2–4 个选项 + 可自由补充），进度条 | 覆盖率引擎逐轮选题，12–18 轮 | 无（对话只在本地） |
| 5 免费报告 | 风险地图（6 维红黄绿 + 总分）+ Top 3 风险 + 「1 元解锁完整报告」 | 生成概览版 | 匿名事件：`preview_shown` |
| 6 支付 | 1 元支付页 + 服务说明 + 退款说明 | — | 订单表 `pending` |
| 7 完整报告 | Top 5 + 90 天行动清单 + 家庭风险预算区间 + 预约/客服 | 生成完整版 | 订单表 `paid`；匿名事件：`report_unlocked` |
| 8 预约 | 称呼 / 手机号 / 方便时间 / 最想问的问题 | — | 预约表（加密） |
| 9 结束 | 「已收到，我会在 24 小时内联系你」+ 客服入口 | — | 匿名事件：`booking_created` |

### 5.1 会话状态

- 对话历史保存在小程序本地缓存，每轮随请求发送到服务端；服务端**不落库**。
- 会话令牌为签名令牌（HMAC，含 sessionId、签发时间、过期时间），无服务端会话表。
- 客户关闭再打开：本地有缓存则提示「继续上次」或「重新开始」。
- 「清除记录」：清除本地对话、报告、订单缓存；服务器无可清除内容（预约与订单除外，按第 8 节处理）。
- 本地缓存 key：`checkup_history`、`checkup_report_preview`、`checkup_report_full`、`checkup_order`。

## 6. AI 内核

### 6.1 分诊器

**输入**：客户首段话 + 前 3 轮对话。

**输出**：

```json
{
  "primaryDomain": "retirement",
  "secondaryDomain": "inheritance",
  "confidence": 0.72,
  "signals": ["孩子已工作", "自己快退休", "担心钱被挥霍"]
}
```

**风险域**：保障、医疗、教育、养老、传承、家企、婚姻。

**规则**：

- 先规则匹配（关键词 + 字段），再由 LLM 复核，避免单靠模型判断。
- 主域最多 2 个；置信度 < 0.5 时继续用开放式问题探测。
- 分诊结果只影响追问优先级，不直接写进报告结论。

### 6.2 覆盖率引擎

**覆盖维度（10 个）**：

| 维度 | 关键字段 | 权重 |
|---|---|---|
| 家庭结构 | 年龄、婚姻、子女、父母 | 高 |
| 收支 | 收入来源、年收入、月支出 | 高 |
| 负债 | 房贷、车贷、经营负债、担保 | 高 |
| 保障 | 医保、医疗险、重疾险、意外、寿险 | 高 |
| 健康 | 体检异常、既往症、家族病史 | 中 |
| 教育 | 子女年龄、教育阶段、留学计划 | 中 |
| 养老 | 退休年龄、养老金、养老方式 | 中 |
| 传承 | 子女婚姻、资产归属、传承意愿、遗嘱 | 高 |
| 企业 | 经营、股权、家企混同、接班 | 中 |
| 婚姻 | 婚姻状态、婚前/婚内资产、配偶债务 | 中 |

**选题规则**：每轮从问题库中选择信息增益最高的问题。

```text
score = 维度权重 × (1 - 维度覆盖率) × 分诊相关度 × 问题新鲜度
```

**收口条件**（满足任一）：

1. 主域覆盖率 ≥ 0.75，且整体覆盖率 ≥ 0.5；
2. 已问 18 轮；
3. 客户说「差不多了 / 直接出报告」；
4. 连续 2 轮回答信息量过低。

**问题库**：每个维度 3–5 个问题，每个问题含：id、维度、字段、题干、选项（2–4 个）、自由补充提示、权重。AI **只能从问题库里选题**，可以改写措辞使其自然，但不能自创风险结论或产品信息。问题库是版本化资产，放在 `src/lib/checkup/question-bank.ts`。

### 6.3 问题树示例

**保障域**

> 如果家里主要收入的人明天突然不能工作 3–6 个月，房贷和生活费能撑多久？
> - 3 个月以内
> - 3–6 个月
> - 6–12 个月
> - 1 年以上
> - 说不清

追问：靠什么撑？（存款 / 家人支持 / 借钱 / 保险 / 没想过）

**传承域**

> 你有没有认真想过，家里的钱将来怎么给到孩子？
> - 已经写进文件（遗嘱/信托/保单受益人）
> - 口头跟家人说过
> - 想过，但没安排
> - 还没想过
> - 孩子还小

追问：你最担心的是孩子拿到钱之后发生什么？（被分走 / 被挥霍 / 不会管 / 家庭纠纷 / 没担心）

**家企域**

> 你或家人名下有没有企业经营？企业借钱时，有没有用个人或家庭资产做过担保？
> - 没有企业
> - 有企业，没做过个人担保
> - 有企业，签过个人担保/抵押
> - 不确定 / 记不清

| `fear_pressure` | 再不买就晚了、出事了就完了 | 删除并重写 |
| `legal_advice` | 我建议你这样立遗嘱、一定有效 | 改为「建议咨询律师/公证」 |

**两道闸**：Prompt 内约束 + 生成后扫描。扫描命中 → 让模型重写一次；重写仍命中 → 返回安全兜底文案。报告末尾必须带固定免责声明。

### 6.6 报告生成

**输入**：

- 对话摘要（结构化 JSON：按 10 个维度整理客户回答，不含姓名手机号）
- 分诊结果 + 风险地图评分
- 知识包片段
- 合规指令

**评分方式**：规则优先、模型辅助。

- 每个维度按答案映射到红/黄/绿，并给出分数（0–100）。
- 模型只负责「解释为什么」和「建议动作」，不改变规则评分。
- Top 5 风险按「严重度 × 紧迫度 × 可行动性」排序。
- 预算公式：`min = 家庭年结余 × 10%`，`max = 家庭年结余 × 20%`；结余 = 年收入 − 年固定支出 − 负债年还款。公式可配置，报告注明口径。
- 法条引用必须来自知识包中的法规底库，并标注「不构成法律意见」。

**输出 JSON Schema（简化）**：

```json
{
  "profile": { "familyStructure": "...", "lifeStage": "...", "summary": "..." },
  "riskMap": [
    { "dimension": "保障", "level": "red", "score": 42, "reason": "..." }
  ],
  "topRisks": [
    {
      "title": "...",
      "severity": "high",
      "phenomenon": "...",
      "whyItMatters": "...",
      "ifIgnored": "...",
      "suggestedAction": "..."
    }
  ],
  "actionPlan": [
    { "period": "30天内", "action": "...", "owner": "客户/家人" }
  ],
  "budgetRange": {
    "min": 12000,
    "max": 24000,
    "basis": "按家庭年结余的 10%–20% 估算",
    "disclaimer": "预算参考，非保费报价，非产品推荐"
  },
  "nextStep": "...",
  "disclaimer": "..."
}
```

**两版生成**：

- 免费版：`profile` 摘要 + `riskMap` + `topRisks` 前 3 条。
- 完整版：`topRisks` 前 5 条 + `actionPlan` + `budgetRange` + `nextStep`。
- 服务端分别调用，**不在前端隐藏完整版内容**。

### 6.7 模型与成本

- 模型：`deepseek-v4-pro`（现有 `src/lib/ai-client.ts`）。
- 问下一题用非思考模式（低温度、快）；生成报告用思考模式（高质量）。
- 固定 System Prompt 放在最前，利用前缀缓存。
- 单次测评约 20–40k tokens，成本约 ¥0.1–0.3；1 元定价可覆盖，且主要作用是过滤与承诺。
- 限流：每 openid/IP 每天最多 3 次测评、1 次完整报告；防刷。

## 7. 报告

### 7.1 结构（完整版）

1. **封面**：家豪 AI 家庭风险测评报告 + 日期 + 「AI 辅助生成」标识
2. **01 家庭画像**：家庭结构、人生阶段、一句话总结（客户可核对）
3. **02 风险地图**：6 维（家庭结构 / 保障 / 现金流 / 教育 / 养老 / 传承）红黄绿 + 分数
   > 6 维由 10 个覆盖维度聚合：家庭结构（家庭结构+婚姻）、保障（保障+健康）、现金流（收支+负债）、教育、养老、传承（传承+企业）。
4. **03 Top 5 风险**：每条 = 现象 / 为什么重要 / 不处理的后果 / 建议动作
5. **04 90 天行动清单**：3–5 条，按优先级，写明谁来做
6. **05 家庭风险预算区间**：基于收支结余；标注「预算参考，非保费报价，非产品推荐」
7. **06 下一步**：预约一对一 / 先问一句
8. **07 免责声明**：AI 辅助生成、不构成产品推荐/投保建议/法律意见

### 7.2 长度与形式

- 3–5 屏，正文不超过 2000 字。
- 交付形式：
  - 小程序内页面（主）
  - 保存长图（canvas 2D 渲染，供客户转发给家豪或家人）
  - 复制文字（兜底）
- 分享：只分享小程序，不分享带内容的报告链接（零存储约束）。

### 7.3 免费版 vs 完整版

| 内容 | 免费版 | 完整版 |
|---|---|---|
| 家庭画像 | 摘要 | 完整 |
| 风险地图 | 6 维红黄绿 + 总分 | 6 维红黄绿 + 分数 + 解释 |
| Top 风险 | 前 3 条（只给标题与一句话） | 前 5 条（现象/为什么/后果/建议） |
| 90 天行动清单 | 不给 | 给 |
| 预算区间 | 不给 | 给 |
| 客服入口 | 给 | 给 |
| 预约 | 不给（客服可人工引导） | 给 |

## 8. 数据与隐私

### 8.1 原则

1. **对话内容零存储**：不写数据库、不写日志、不写埋点 payload。
2. **报告只在客户手机**：小程序本地缓存；服务器不保存。
3. **最小必要 PII**：只有支付需要 openid；只有预约需要称呼、手机号、时间。
4. **可删除**：本地可一键清除；预约可联系家豪删除。
5. **预留 C**：数据层抽象为 `CheckupSessionStore` 接口，V1 用 `NoopStore`，未来可替换为加密存储。

### 8.2 表结构

```sql
-- 1 元订单（不含对话内容）
CREATE TABLE IF NOT EXISTS checkup_orders (
  id SERIAL PRIMARY KEY,
  order_no TEXT UNIQUE NOT NULL,
  openid TEXT NOT NULL,
  amount_cents INTEGER NOT NULL DEFAULT 100,
  status TEXT NOT NULL DEFAULT 'pending'
    CHECK (status IN ('pending','paid','cancelled','expired','refunded')),
  session_id TEXT NOT NULL,
  payment_method TEXT DEFAULT 'wechat',
  payment_ref TEXT DEFAULT '',
  paid_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  expires_at TIMESTAMPTZ NOT NULL DEFAULT (NOW() + INTERVAL '30 minutes')
);

-- 预约（PII 加密存储）
CREATE TABLE IF NOT EXISTS checkup_appointments (
  id SERIAL PRIMARY KEY,
  name_enc TEXT NOT NULL,
  phone_enc TEXT NOT NULL,
  time_window TEXT NOT NULL,
  question TEXT DEFAULT '',
  openid TEXT DEFAULT '',
  status TEXT NOT NULL DEFAULT 'new'
    CHECK (status IN ('new','contacted','scheduled','done','invalid')),
  admin_note TEXT DEFAULT '',
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 匿名事件（不含对话内容）
CREATE TABLE IF NOT EXISTS checkup_events (
  id SERIAL PRIMARY KEY,
  session_id TEXT NOT NULL,
  event_name TEXT NOT NULL,
  payload TEXT NOT NULL DEFAULT '{}',
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

### 8.3 保留期

- `checkup_events`：180 天，仅保留行为统计。
- `checkup_orders`：按支付/财务要求保留，不含对话内容。
- `checkup_appointments`：处理完成后 180 天；客户要求删除时立即删除。
- 本地缓存：客户清除即删除；小程序卸载即删除。
- 清理方式：V1 用 Vercel Cron 或后台手动清理；上线前配置，避免无限增长。

### 8.4 日志

- 禁止打印 prompt、对话内容、姓名、手机号、报告正文。
- 只允许打印：sessionId 前 8 位、模块 id、token 数、耗时、错误码。
- 错误日志统一脱敏函数。

### 9.2 前端页面

| 页面 | 路径 | 内容 |
|---|---|---|
| 首页 | `pages/index/index` | 品牌、介绍、隐私承诺、免责声明、开始测评 |

### 9.3 后端接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/checkup/session` | 开始测评，返回签名 sessionToken + 开场白 |
| POST | `/api/checkup/answer` | 提交回答，返回下一题或收口信号 |
| POST | `/api/checkup/preview` | 生成免费版报告 JSON |
| POST | `/api/checkup/order` | 创建 1 元订单，返回支付参数 |
| GET | `/api/checkup/order/status` | 查询订单状态 |
| POST | `/api/checkup/unlock` | 校验已支付 + sessionToken，生成完整报告 JSON |
| POST | `/api/checkup/appointment` | 创建预约（加密存储） |
| POST | `/api/checkup/event` | 匿名事件上报 |
| POST | `/api/checkup/pay/notify` | 支付回调（验签、幂等） |
| GET | `/api/admin/checkup/appointments` | 管理后台预约列表（`ADMIN_KEY`） |
| GET | `/api/admin/checkup/stats` | 匿名统计（`ADMIN_KEY`） |

**会话**：无状态签名令牌（HMAC-SHA256，`SESSION_SECRET` 派生），含 `sessionId`、`iat`、`exp`；对话历史由客户端每轮携带。

**幂等与防刷**：

- 订单：`order_no` 唯一；回调按 `status='pending'` 条件更新，防重复入账。
- 完整报告：一个订单只能解锁一次；订单与 `sessionId` 绑定。
- 限流：复用 `rate-limit`，按 openid + IP 双维度。

**登录与 openid**：进入测评不登录；点击支付时调用 `wx.login`，用 code 换取 openid（复用 `/api/auth/wechat-login`，不要求手机号），仅在订单中保存 openid。

**失败处理**：

- AI 超时/失败：返回兜底文案，允许重试，不扣费。
- 报告生成失败：订单保持 `pending`，允许重试或后台人工退款。
- 支付回调失败：依赖微信重试 + 后台补偿任务。
- 客户端网络中断：本地保留对话，恢复后可继续。

### 9.4 支付

- 优先使用微信 **虚拟支付**（与现有积分充值一致，需确认新商品/类目是否支持）。
- 若类目不支持虚拟支付，改用 **微信支付 JSAPI**（「报告生成服务费」按服务类目）。
- 抽象 `PayProvider` 接口，V1 实现一种，避免回调逻辑与支付方式耦合。
- 支付回调必须验签、幂等；前端只轮询订单状态，**不得由前端直接解锁**。
- 1 元订单超时 30 分钟自动过期；报告生成失败可人工退款（V1 后台手动处理）。

### 9.5 后台与通知

- 在现有 `/admin` 增加「测评预约」标签页：列表、详情、状态流转、备注。
- 预约通知（V1 任选其一，不阻塞）：
  - 后台列表 + 手动刷新（保底）
  - 企业微信群机器人 webhook

- 匿名统计：开始数、完成数、预览数、付费数、预约数、各维度分布、流失轮次。

| 保存长图开发量大 | 延期 | M4 前做 canvas 2D 技术验证；验证不通过则降级为复制文字，验收记录注明 |
| 1 元支付复杂 | 上线延期 | 优先虚拟支付；备选 JSAPI；极端情况 V1 免费 + 预约 |
| 旧版用户投诉 | 口碑风险 | 上线公告 + 客服解释；用户已确认直接切换 |
| 模型成本超预期 | 亏损 | 限流 + 轮次上限 + 缓存 |
| 微信审核不通过 | 无法上线 | 名称/类目/介绍按安全版；备选名称 |

## 15. 验收标准

### 15.1 功能

- [ ] 新客户无需登录可在 1 分钟内开始测评。
- [ ] 完成 12–18 轮问答，中途可暂停、继续、退出。
- [ ] 免费版报告包含风险地图 + Top 3；完整版包含 Top 5 + 行动清单 + 预算区间。
- [ ] 1 元支付成功后 5 秒内解锁完整报告；支付失败可重试。
- [ ] 预约提交后后台可见，且手机号加密存储。
- [ ] 本地可清除记录；清除后重新打开为初始状态。
- [ ] 报告可复制文字；保存长图可用（若 canvas 技术验证失败，降级为复制文字并在验收记录注明）。

### 15.2 合规

- [ ] 报告与对话合规扫描 0 红线。
- [ ] 无产品名、公司名、费率、收益承诺、联系方式。
- [ ] 每份报告带免责声明与 AI 标识。
- [ ] 个人介绍不亮未授权身份。

### 15.3 隐私

- [ ] 数据库无对话内容、无报告正文。
- [ ] 日志无对话内容、无 PII。
- [ ] 预约 PII 加密存储，仅管理员可解密。
- [ ] 客户可删除本地记录；预约可申请删除。

### 15.4 性能

- [ ] 首页首屏 < 2 秒（4G）。
- [ ] 每轮问答响应 < 5 秒（P90）。
- [ ] 报告生成 < 20 秒（P90），有进度提示。
- [ ] 支付回调幂等，重复回调不重复入账。
